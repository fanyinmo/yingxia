# 动态与实况图集

本版已移除实况照片保存和动图转实况。保留静图、原格式动图、无声 MP4、GIF、单项保存及 BGM 合成。动态卡片只提供保留动态素材和 GIF；批量保存默认保留已有格式，未分类片段保存为无声动图。旧记录与旧文件保留；读取内嵌动态片段只用于兼容预览或 GIF／BGM 输入，不再生成实况照片。

当前正式版为 **1.2.0 / code 42**，本地安装包与源码位于 `outputs/latest/`，采用用户确认的 rc21 功能。本轮模拟器实际结果及限制见 [电脑验证](testing/EMULATOR_RC21.md) 和 [最新版说明](CURRENT_VERSION.md)。

## 自动识别与失败重试


图集完成快速解析后自动检查当前作品的动态来源，不发布文件或创建记录；普通视频不做图集动态检查。读取中显示进度，用户可跳过；未完成时不优先提供把静态封面当动态素材的保存或合成操作。成功后直接显示对应保存方式，动态保存置前、静态封面次级。已有明确完整动态来源可跳过重复读取。自动桌面读取最长 15 秒，手动重试最长 30 秒，来源完成后仍需实际媒体校验。


移动分享页解析失败但作品 ID 已确认时，首页也可主动检查同 ID 官方桌面页，取得图集后再保存，不要求先有移动页封面。作品 ID 未确认时不猜其他作品。失败、超时、验证或跳过后保留现有图片，显示“重新检查动态资源”等恢复操作；不把只保存封面称为动态成功。批量在自动检查结束后继续后续任务，失败项不阻塞整组。

读取期间可取消；页面或资源不可用时提示原因并保留原结果，已有静图或明确选择的静态封面仍可保存，也可重试读取。遇到实际验证码或登录门槛，可点“打开抖音验证页面”，由用户在官方页面手动完成后“继续读取”。App 不自动登录或解验证码，常驻登录按钮不会触发门槛。这条手动路径目前只用受控页面验证，尚未实测真实网络验证码。


图片数组必须完整保留，作品 ID、页面归属和图片身份均需匹配。同图后续数据只按准确图片键补充，不按列表位置与移动页拼接，也不使用推荐作品、全局 BGM 或通用播放器替代短片。仅同图 camelCase 播放地址可提供受限的 CLEAN 播放角色，必须是该片段播放地址的子集；原签名 URL 不改写，下载继续遵循既有域名、水印、HTTPS 和每次跳转检查。候选元数据仍需下载与实际解码后才能证明动态内容。

rc12 增加已知分类保持：同作品的桌面候选为 `DYNAMIC` 且有自身片段时，只有两侧图片数组中均唯一、相同且非空的 `imageKey`，才能继承移动页已明确的 `LIVE` 或 `ANIMATED`。不按序号、封面 URL 或片段 URL 猜身份；空键、重复键、不同作品、冲突键、缺片段或原类型未知均不提升分类。桌面候选已明确的类型不覆盖；只保留类型，不替换桌面媒体、元数据或顺序。新增7项JVM与1项引擎回归已在rc12实际构建及执行中通过；rc13结果另按新APK登记，不迁移旧候选计数。


同一张图自身 `video` 及其 `bitRateList`／`bit_rate`／`bitrate` 中的已提供来源，按分辨率、帧率、码率、文件大小依次优先排列。未知、非法或相同质量数据保持原顺序；不改写签名，不用其他图片、作品全局视频或 BGM 补充质量。元数据用于候选排序，实际下载尺寸、帧率仍以编码视频为准；高质量候选失效时可能使用该图的可用备用来源。

## 原始资源与画质边界




普通视频保留严格数字冷 CDN 的 HTTPS 58001 跳转兼容与提前断流处理：限定节点采用 1 MiB 分段，校验强 ETag、If-Range、字节范围和总长度，每段最多两次重试，总期限十分钟。缺少可靠文件标识时回退完整 GET；200 响应只能从零完整重写。rc5 的共享传输也服务 GIF 来源及逐图片段，所有请求沿用同一来源门禁，并未将所有地址都改为分段。完整媒体检查后才发布，失败或取消清理本次临时文件。

## GIF 导出与播放时长

普通视频可正常下载，也可“保存 GIF”。展开截取设置输入起始与时长，精确到 0.1 秒，默认从开头最多 6 秒；最长可覆盖完整视频，从中间开始时以剩余时长为上限，不再限制 15 秒。读取实际视频后再次确认范围，至少 0.1 秒，不会把封面改扩展名冒充动画。长 GIF 仍受文件大小、存储和设备能力限制，不承诺任何长视频都能完成。

动态图集明确选择“GIF 动图”后，将对应短片或原动画转换为所选画质的 GIF，各项默认采用自身原时长。已有 GIF 在分享模式或修改时长时会重新编码；需要原字节应选择保留动态格式。混合图集中的静图仍保存为图片，每个动态项导出自己的 GIF，不把整组误称为一个合成 GIF。多张全静图则提供“图片序列合成 GIF”，按顺序合成一个循环 GIF，可设置 0.1 秒/张，单轮总时长为各张停留时长之和。单张纯静图没有可恢复的运动，不生成重复封面的假动图。

每项自定义时长用于 GIF 转换和 BGM 合成：静图序列表示每张停留多久，逐动态项 GIF 表示该动画导出多久，BGM 视频总长为各项之和；正常保留动态格式仍保存原片段时长。动态时长与设置不同会截取开头或循环，先弹窗“设置时长与素材原时长不同”，选择“继续”或“返回修改”，不当作输入错误。返回修改不会发布本次文件或新增记录。

转换在手机本地解码真实画面并编码为循环 GIF89a，无声音，保留比例且不放大小图。界面默认“分享”：最长边 480 像素、最高 10fps、每帧最多 128 色；可选“清晰”：960、30fps、256 色。来源帧率更低时不虚增。编码使用局部自适应调色板和有界字典，减少固定颜色映射与内存开销，但 GIF 仍不能无损保留照片颜色。GIF／WebP／APNG 的转换读取实际动画帧，按叠加、清除规则还原画面，不依赖实时截图。

两档保留所选总时长，不表示保留每个源帧或精确的最后一帧。GIF 延时以 10ms 表示，累计时间允许相应取整差异。普通视频 GIF 来源和输出各不超过 2 GiB；逐图片段仍遵循 128 MiB/60 秒限制。临时源文件在私有缓存，结束或取消清理，只发布最终 GIF。生成有进度并可取消；记录保存 GIF 档位、截取范围及图集时长，不同参数分别检查重复。

QQ／微信的自动播放取决于文件与发送入口，秒数或体积均不是单独的通用判据。导出后提示实际体积；可缩短片段、选择分享档或使用 MP4，但不承诺所有入口自动播放。

### rc11 真实 GIF 体积对照

同一“命数如织”网页源为 960×720、1,861,995 字节，容器时长 2,949ms，88 个视频帧全部顺序解码。转换选择整个容器时长，产物独立检查如下：

| 档位 | 尺寸 | 完整解码帧数 | 单轮时长 | 字节数 |
| --- | --- | ---: | ---: | ---: |
| 清晰 | 960×720 | 89 | 2,950ms | 20,263,842 |
| 分享 | 480×360 | 30 | 2,950ms | 1,871,200 |

两个 GIF 的全部帧可读取，尺寸一致、延时为正、循环与文件尾完整；实际画面有变化。分享版比清晰版小 90.77%，只针对这条素材。清晰有 87 个不同解码画面，分享有 30 个；不能把完整产物解码称为源的 88 帧全部保留。分享版减少像素、采样帧及颜色细节，以体积换取兼容性，不是原画保存。详细本地证据为 `outputs/reports/emulator-rc11/real-gif-independent.json` 与同名 `.md`，不含聊天 App 的发送验收。

图集分享响应只提供静态封面时，无论保存为 GIF、WebP 还是 MP4，都无法恢复不存在的动态帧。rc2 历史测试中，“苹果动态循环”（7648537782562529274）和“命数如织”（7689306999973377371）的公开移动页均只有一张单帧 WebP，无逐图视频；rc3 后续从同作品桌面页取得独立短片，解决了这三条样例的来源缺失。“马达加斯加企鹅”（7483745350491049276）返回普通视频，适用原有视频转 GIF。移动页结论不推断抖音 App 内的作品也是静态。


## 保存与预览

- **普通图片**：按实际图片格式保存；明确选择“仅保存静态封面”时生成 JPEG。
- **GIF、动态 WebP**：保留原始字节及所有帧，下载记录可全屏播放、暂停；离开页面或切到后台暂停。
- **APNG**：保留原 PNG 动画文件。Android 系统不支持播放时明确提示，下载文件仍保留动画；不把静态预览宣称为动画播放。用于 GIF 转换或 BGM 合成时读取真实动画帧，以累计时间边界换算毫秒，避免逐帧取整累积漂移；亚毫秒帧不强制补成 1ms。受控样例中 300 帧、每帧 1/30 秒保持为 10,000ms。
- **视频型动图**：保存无声 MP4，保留压缩视频轨、尺寸、比例与帧率；记录可播放动图。


GIF／动态 WebP 相册预览先复制到本次预览独占的私有缓存，复制完成即关闭相册源输入，再从副本解码。退出时释放动画并清理副本，不让持续播放长期持有 MediaProvider 原文件句柄；这一调整也修复了动画预览后删除本次测试文件时等待不结束的问题。



GIF/合成视频的重复检查包含播放时长，视频 GIF 还包含截取范围。时间不同或旧记录没有时间信息时不会阻止导出；原记录与文件保留。失败/取消只清理本任务文件，已发布但记录写入失败时保留文件并提示到保存目录查看。

## rc1 与 rc2 历史验证

rc2 在用户的红米 Android 16 上完成企鹅普通视频的“解析→CLEAN 下载→本地转换→相册发布→动画解码”流程：生成 480×270、44 个不同画面、约 5.44 秒的循环 GIF。修复了冷 CDN 的 32／48 位十六进制 relay 地址格式；最终实际跳转未发生域名拒绝。16 项受控原生场景通过，具体范围及当时未取得真实动态图文来源的限制见 [验证记录](VALIDATION.md)。


生成小型动画测试文件：`python scripts/generate_dynamic_album_fixtures.py`。原生测试类为 `DynamicAlbumSaveTest`、`DynamicAlbumPreviewTest`、`DynamicAlbumRecordsTest`；SAF 测试需要显式提供单独授权的测试目录，默认跳过。


rc1 修正了原流程只保留短链编号、丢失官方图文路径的问题。普通快速解析继续保留同作品完整移动分享 URL 及原参数，普通桌面分享入口仍回到移动页；确认视频页连续返回空错误时，再对同一作品补试官方图文页一次。rc3 的按需桌面读取是独立入口。

rc1 阶段，MuMu Android 15、WebView 110 对同一作品仍返回空错误页，详情接口 HTTP 403。rc2 改在用户连接的红米 Android 16、WebView 153.0.8010.36 测试，三条图文均能解析为同 ID 图集，但只读到静态图片与 BGM，没有逐图 motion。不能把静态图解析成功或受控素材测试计为真实图集动态保存成功。

rc2 另外完整读取三作品的移动展示与下载原地址，核对 12 个 JPEG/WebP 文件共 746,606 字节：JPEG 的结束标记后没有尾部，WebP 容器只有静态 VP8 块，没有动画块、XMP 或附加视频；未发现 MotionPhoto/MicroVideo 或 MP4 容器。检查只针对当次官方移动响应，不能推断抖音客户端中的作品也是静态；rc3 的运动内容来自另行取得的桌面逐图视频，没有从这些静态封面恢复或伪造帧。
