## 2 USB测试准备与数据保护

1. 用户说开始测试后，读取 adb devices -l，明确手机 serial 和型号。所有设备命令显式绑定该手机，不能误用同时连接的 MuMu。

2. 记录 App 版本、APK SHA256和签名、Android/API、HyperOS、相册和 WebView、屏幕/字体/方向、网络、通知授权与可用存储。先等待原任务结束。

3. 记录并在可用权限内备份准确的 App 偏好、背景私有副本和历史，保存本地摘要；无访问权限时记录限制及 UI 快照。保留原 APK 和原文件清单，不扫描或搬走个人相册。

4. 使用同签名覆盖安装，禁止卸载、pm clear、清抖音数据或整目录删除。覆盖后马上核对旧设置、背景、路径、记录及文件仍在。

5. 建立本轮独立测试子目录和唯一文件名前缀，例如 YX_T3_日期_用例号；通过系统选择器授权。默认相册和自定义目录分别测试，本轮准确 URI 和记录单独登记。

6. 测试删除、网络失败、低存储和大文件边界仅针对明确本轮产物或受控测试层，不填满个人手机、不改变其他 App 权限。原网络、方向、字体、通知和保存路径逐项记录并还原。

7. 官方登录和验证码出现时由用户手动完成；不自动操作密码、短信或验证码。未遇到真实门槛时保留未触发记录，不将受控页面当作真实验证通过。

## 3 资源分类与默认规则

| 类型 | 判据 | 正常保存预期 |
| --- | --- | --- |
| 普通视频 | 同作品可解码连续视频轨 | 默认可用 CLEAN 来源 MP4；没有有水印/原始版本选项 |
| 静图 | 真实单帧原图片，且没有同图动态 | 按实际图片格式保存；全静图不展示原动态保存面板 |
| 原生 GIF WebP APNG | 真实多帧容器和时间轴 | 原文件保留；APNG原文件保留和系统可播放分别记录 |
| 已知视频型动图 | 官方逐图动画类型明确且片段属于该图 | 无声 MP4，视频轨保留；原音轨去掉 |
| 已知实况 | 官方逐图实况类型明确，封面片段对应 | 单个 _MP.jpg；保留内嵌原片段及声音；不能由两文件替代 |
| 未知动态 | 有同图片段但来源未明确类型 | 用户选择实况照片、无声动图或 GIF；选择不反推来源类型 |
| 混合图集 | 各项分别分类，保留来源顺序 | 按各项格式保存；未知项选择不改变已知项 |

| 项目 | 当前规则与验收要求 |
| --- | --- |
| 视频 GIF 起始和时长 | 0.1 秒精度；默认从开头最多6秒；最长为真实视频全长，从中间开始为剩余时长 |
| 动态图原保存 | 保留实际来源尺寸、比例、帧率/时轴；GIF转换是独立兼容操作 |
| GIF 兼容输出 | 界面默认分享480/10fps/128色，可选清晰960/30fps/256色；无声、不放大、低帧率不虚增；所选总时长按10ms精度表示，不等于逐一保留源帧 |
| 静图序列 GIF | 至少2张时输出1个GIF，顺序轮播；0.1秒/张允许；单轮时长为各张时长之和 |
| 动态 GIF | 每个动态项独立GIF；分享档或自定义时长可重新编码原GIF；原格式保存保留原字节；混合中的静图仍图片 |
| 动图转实况 | 独立入口；真实首帧与时间戳配对、去音轨、单JPEG；不反向认定来源为原生LIVE；红米相册播放另验 |
| 未知片段生成实况 | DYNAMIC已有非空同图片段时，另提供整行“用动态片段生成实况”和单项入口；主动用首个真实解码帧生成新封面；原3格式不变，STATIC／LIVE无此按钮 |
| 自动动态识别 | 图集快速解析后自动检查，同作品同图；进度与跳过；取消/失败/超时保留原结果并可重试，不保存文件，批量继续 |
| 合成自动时长 | 动态各自实际原时长；静图当前内部默认3秒；总时长相加 |
| 自定义时长 | 每项统一播放时长0.1至120秒，精度0.1；缩短截取开头，延长循环，速度不变 |
| 确认弹窗 | 设置时长与素材原时长不同；继续 或 返回修改；返回不发布文件和记录 |
| BGM | 只用同作品可用BGM循环至结尾，源片段原音轨不混入；实况独立视频合成不替代照片 |
| 预览快进后退 | 分别1至120秒；默认各10秒；5/10/15/30/60快捷值在一行同时修改两个方向 |
| 限额 | 100项图集；图片32MiB；动态128MiB及60秒；图集输入512MiB；BGM64MiB；合成15分钟；视频GIF来源和GIF输出各2GiB |

### PR01 真实作品核对

1. 官方抖音打开原链接，记录作品ID、作者、标题、项数、是否能播放/保存及BGM。

### PR02 单条保存和媒体核验

1. 首页粘贴并解析，检查ID和资源卡片；视频/图集分别选择适用保存。
2. 用本轮唯一名字保存，在历史及系统相册打开，核对完整画面、声音、尺寸、比例、帧率和时长。

### PR03 图集动态及实况

1. 快速解析后观察图集自动检查动态来源，无需额外点击；检查不保存文件。另测跳过、失败后手动重试与移动失败但ID明确的恢复。
2. 未知项选输出格式；已知项保持各自类型。预览切到指定项单独保存，文件编号与原索引相符。
3. 实况检查单JPEG的XMP、兼容元数据、封面时间匹配及内嵌视频，再验App播放与红米相册标记、长按、重开。动图转实况另测真实首帧和无声音；已内嵌源实况核对完整摘要。通过系统分享菜单观察格式，需发送时由用户操作。

### PR04 GIF及BGM时长

1. 记录源实际时长和动态轨，再设0.1秒精度时间。视频测试起始0.0、中间、最后0.1及全长；超范围明确拒绝。
2. 图集默认动态各自时长、静图默认，合成总和；统一时长不同则先说明短截/长循环，返回不输出，继续才保存。
3. GIF分享和清晰档分别逐帧检查变化、比例、正延时、循环及累计时间；记录体积，不用一个固定体积比作为所有素材预期。QQ/微信每个实际发送入口分别记录播放结果；BGM验证真实动态帧、顺序和配乐循环，原音轨不混入。

### PR05 批量

1. 原五条视频按 S09 S10 S11 S08 S12 加入，另加入静图及动态样例；开始前拖动、上下移和左右滑删。

### PR06 失败与复测

## 7 当前待核查事项

设置要求 K01：当前已提供“静图默认播放时长”输入和圆形滑块，范围0.1–120秒、精度0.1秒。源码入口完成不等于手机验收通过，仍按UI-H13检查输入、持久化、自动建议与统一时长优先级。

真实样例缺口 K02：原生GIF/WebP/APNG、官方明确已知LIVE或ANIMATED、多项全动态和混合图集仍需现场核对或补链。S20是新增十项实况题材候选，不能仅凭标题填已知实况。受控素材覆盖不能被写成公开源通过。

兼容待测 K03：红米相册的原生实况标记、长按、重开和分享保留动态；Android16的存储、编解码和后台行为；真实官方验证门槛，都要独立真机结果。

输入边界 K05：未明确动画类型且没有逐图片段的原生GIF，在实际下载解码前可能显示STATIC；明确LIVE的内嵌JPEG若无外部motion，当前下载前置检查可能阻断。下载层原文件字节保留不证明完整解析入口支持，尚无真实公开样例闭环；保留缺口，不以受控素材冒充全原生输入通过。
