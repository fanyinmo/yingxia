# 影匣 1.1.0-rc3 历史候选验证记录

日期：2026-10-04。包名 `com.local.douyinsaver`，versionCode 19、min SDK 29、target SDK 35。第二次正式版本仍为待发布的 **1.1.0**，手机确认后再生成正式包并上传；本轮未推送、打标签或创建 Release。相对首版的变化见 [CHANGELOG](CHANGELOG.md)。

## 图文解析拒绝的根因与修复

手机 1.1.0-rc2 日志对应作品 `7692342361661597922`，已返回完整分享页，`albums=1`、`images=1`、`bgm=true`。它在进入图片网络传输前，由 SaverEngine 的 CLEAN 来源可用性检查拒绝。旧的 `imageSources()` 只有同时找到明确水印下载变体，才把独立的官方展示地址归类为 CLEAN；普通只有展示字段的图集被保留为 ORIGINAL，导致单次和批量的共同入口一起失败。`structured=false` 指视频结构字段，不表示图集未找到；CSP report-only 提示和 BGM 子资源网络错误均不是这次来源分类拒绝的触发点。

已读取实际官方 [note 前端脚本](https://lf-douyin-mobile.bytecdn.com/obj/growth-douyin-share/growth/douyin_ug/static/js/async/note_(id)/page.20343a52.js)：展示图优先取 img_bitrate 的 gear_480p.images，否则用 images；原图下载字段按图片 URI 配对，BGM 来自同作品 play_addr。该页面渲染展示图片不要求同时存在带水印下载变体。

本候选只对已经通过当前作品归属和 URI 配对的官方展示字段，排除显式水印变换与矛盾/未知水印开关后，保留 CLEAN 来源。展示与下载字段指向同一请求（含 fragment 差异）时不再同时标为 CLEAN 和 WATERMARKED；签名地址不改写。没有角色证据的扁平地址及未分类 download-only 地址仍不自动升级，缺少任一可用图片仍拒绝整套图集，不静默删图。补充了带水印的官方图片模板名与编码标记检查，避免用 `wm=0` 绕过已知水印指令。

这里的 CLEAN 是来源选择，不能保证作者原图没有 Logo 或文字，也没有进行像素编辑。上一候选的冷 CDN 地址兼容保留。新增 `album_sources` 诊断仅记录图片数量、来源数量与是否找到 BGM，不输出签名图片地址、Cookie 或音乐参数。

# 影匣 1.1.0-rc2 历史候选验证记录

日期：2026-10-04。包名 `com.local.douyinsaver`，versionCode 18、min SDK 29、target SDK 35。第二次正式版本仍计划为 **1.1.0**，等手机测试确认后才生成正式包并上传 GitHub；本轮未推送、打标签或创建 Release。相对首版 1.0.0 的变化见 [CHANGELOG](CHANGELOG.md)。

## 已定位并修复的原因

手机 1.1.0-rc1 新诊断揭示作品 `7692429893640009190` 的来源链路：`aweme.snssdk.com` → `v5-coldx.douyinvod.com` → `bdcgslb.com` 下的动态子域。分享页已经给出目标作品数据；失败原因是 App 未支持最后一跳的合法 CDN 域名区域，不是 CSP 的 report-only 提示或没有读取到作品。

两个手机日志中的动态主机均以普通 CA/SNI/主机名校验成功建立 TLS 1.3 连接，证书覆盖 `*.bdcgslb.com`，有效至 2026-12-02。直接权威 DNS 查询的 SOA 管理员为 `dnsadmin.bytedance.com`，NS 为 Volc-DNS；Verisign RDAP 记录为 ByteDNS。结合手机从已信任抖音 CDN 的实际重定向，可支持这一区域的兼容性判断；注册记录未披露注册公司的名称，不把基础设施判断写成注册主体确认。核验只请求 HTTPS 根目录 HEAD，返回 403，未请求签名媒体路径、读取正文或下载真实作品；根目录 403 不代表视频不可用。

新规则接受 `bdcgslb.com` 下**单层、有效的 1–63 字符 DNS 标签**，保留 HTTPS、默认或 443 端口、无嵌入凭据的统一要求。根域、多层子域、伪后缀、非法标签和异常端口仍拒绝。不固定随机主机名、43 位长度或前缀，以兼容地址轮换；原始路径、大小写与签名参数不改写。现有可信 HTTP Location 兼容也适用新合法子域：先改为同路径、同查询的 HTTPS，再检查并请求，不发送明文 HTTP。

解析探测、预览准备和下载所用的共享地址门禁同时生效，CLEAN 选择和格式检查保持原规则。动态 CDN 地址过期后仍可从同作品的平台入口刷新；后续未知域、明确水印参数或已分类为其他来源的地址不会被下载探测/共享传输放行。

## 批量版本选择的根因与修复

旧版单个视频的版本按钮会同时写入全局 `watermark_mode`，批量下载又从这个值创建下载选项。因此曾在单个视频选择有水印，会改变之后批量下载和重启后的默认选择。

新版将设置默认、当前单链接和本次批量选择分开。只有设置中的默认选项持久化到 `default_watermark_mode`；单链接改变或清空时重置单次选择，批量选择保持独立。批量任务卡预览、单项保存和全部保存都使用批量区域当前显示的版本，开始保存后锁定本批选项。诊断记录请求版本、默认版本和实际记录的水印分类。

旧 `watermark_mode` 无法区分临时选择和明确设置，保留旧数据但不继承其值；首次升级默认无水印，之后尊重设置中明确选择的新默认。已保存任务可以直接保存另一个版本，同版本的可读取文件会跳过。删除文件、仅移除记录或外部删除后，刷新队列和单链接的重复缓存，避免假判已下载。

## 来源、清空与预览设置

## 视频预览

固定高度的 VideoView 与系统浮动播放条替换为 Media3 ExoPlayer/PlayerView 和主题化控件。预览按视频比例分配画面区域，使用 FIT 保留完整画面；标题、圆角容器、缓冲与播放进度、时间标签和按钮统一排版。画布受当前窗口可用高度限制，横屏仍能完整显示操作区，空余区域统一为黑色留边。

TextureView 配合 Media3 空效果 GL 管线处理解码纹理，避免带旋转元数据的视频在模拟器上被错误旋转或拉伸。GL 模式未发布 VideoSize 时，按实际视频格式、旋转元数据和像素比例计算视图比例。后台返回后对可定位的暂停视频刷新当前帧，偏移仅 1ms；不自动播放，不改变音量，已经播放结束时保留重播状态。

支持拖动时间轴、播放暂停、结束重播、前后跳转 10 秒、静音和放大/收起。拖动时显示目标时间，松手才跳转，不改变原有暂停状态。控制区跟随用户主题色；后台暂停、返回前台不自动播放，关闭或销毁时释放播放器，处理音频焦点和拔耳机暂停。预览仍使用解析结果中当前选择的有水印或无水印来源。
