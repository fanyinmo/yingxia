## 第二版发布要点

- 改进原有批量队列：自动连续解析、集中显示结果、批量保存、长按排序、左右滑动移除与清空全部。
- 重做视频播放器布局与进度控制，保留原画面比例；前进、后退秒数分别保存，提供一行快捷值。
- 下载与预览固定使用 CLEAN 来源；视频确认首个有效地址后停止，失败才尝试同类备用来源。
- 修正图文展示来源被错误拒绝的问题：当前作品的官方展示地址经校验并排除水印标记后可用，不再必须同时读取到明确的水印下载变体；同地址不再产生分类冲突，单条与批量使用同一策略。
- 统一输入框圆角，改为圆形外观滑钮；背景位置只在完整显示时出现，铺满裁剪居中。
- 补充同作品媒体编号与多档地址，兼容已核验的 `bdcgslb.com` 合法单层调度子域；沿用可信 CDN 的 HTTP → HTTPS 跳转兼容，修复长主机名被诊断误脱敏，继续限制未知域名、嵌入凭据与非标准端口。
- 保留旧记录、文件、外观与保存位置，整理必要源码、测试和展示资源。

主题调色盘、背景图片、图集下载与 BGM 合成是首版已有功能，不作为本轮新增功能。此前视频诊断已查明冷 CDN 调度子域被拒的问题，保留已补充的来源规则。本次图文诊断已经读到图片和 BGM，失败发生在图片来源分类，来源规则修复后用户确认候选测试正常。图片保存不依赖 BGM 加载；本次来源修复不代表所有音频网络错误均已解决，合成仍需实际取得可用音频。来源选择也不能移除作者写入画面的标志。发布说明中的“已验证”仅填写实际完成的结果，由 [验证记录](VALIDATION.md) 支持；一般正常反馈不扩写成每条链接和每种保存模式的逐项确认。

## 源码维护

提交应用源码、测试、Gradle Wrapper、构建脚本、使用文档与 README 展示图片。自制 Android 测试素材和 Gradle Wrapper 的 JAR 属于必要文件，应保留在仓库中。

新建的生产代码、测试和布局即使暂未被 Git 跟踪，也属于应保留并提交的项目文件。不要通过删除测试、素材或 Wrapper 来减少仓库体积；功能说明、安装、构建、发布和历史验证文档各有用途，保留并同步版本。

`.gitignore` 排除本地工具、构建缓存、`local.properties`、`outputs/`、临时调试文件和签名密钥。JDK、SDK、个人截图、下载样本与 APK 不作为源码提交。

个人诊断日志、手机偏好备份、旧截图、JVM 故障转储和旧版本安装包放在忽略目录，必要时归档到工程外；正在恢复的状态备份、本机配置和签名不能提前删除。新版本验证完成后，工作区只需保留当前 APK 与最新本地验证证据。

提交前检查实际变更和忽略文件：

```powershell
git status --short
git status --short --ignored
```

继续开发时按 [构建说明](BUILD.md) 配置环境。运行单元测试、解析脚本回归和 Lint；涉及设备行为的改动，再运行对应 Android 测试。更新功能时同步 [使用说明](INSTALL.md) 和 [验证记录](VALIDATION.md)。

## 发布流程

1. 手机候选测试确认后才安排发布。本次 **1.1.0-rc3 / code 19** 已取得用户确认与上传授权，原始反馈保留在验证记录中。
2. 正式配置使用 `versionName 1.1.0 / versionCode 20`，版本文档与实际构建配置一致。
3. 重新构建、验证并核对普通包，生成 `outputs/apk/yingxia-1.1.0.apk`。候选 APK 不直接改名当正式包，正式包检查结果独立记录。
4. 上传已核验的源码，创建标签 `v1.1.0` 和正式 Release，并使用 [CHANGELOG](CHANGELOG.md) 中相对 **1.0.0** 的变化填写发布说明。

正式 Release 附件为 `yingxia-1.1.0.apk`，不上传候选包、独立测试 APK 或 `phonecheck` 变体。发布后核验附件可下载、版本与签名正确，并记录 APK 的 SHA-256；仓库上传、标签创建和附件核验分别以实际执行结果确认。

当前安装包沿用原开发签名，可覆盖先前测试版。后续更新需继续使用相同签名才能覆盖安装；换开发机器可能生成不同 debug 密钥。正式签名与备份见 [构建说明](BUILD.md)，私钥不上传仓库。
